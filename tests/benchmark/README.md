# 분석기 문제지·정답지

음원 분석기의 단계마다 "문제지(입력)"와 "정답지(나와야 하는 결과)"를 두고, 분석 결과를 채점한다.
곡은 모두 코드로 직접 만든 것이라 저작권 문제가 없고 정답이 정확하다.

- 저장소에는 곡을 만드는 MIDI와 정답표(answer.json)만 올린다.
- 음원(wav)은 용량이 커서 `output/benchmark/` 에 만든다(올리지 않음).

## A단계: 소리 분리 (`separation_set.py`)

| 문제 | 들어 있는 악기 | 시험하는 것 |
|---|---|---|
| 01_노래와_피아노 | 목소리(vocals) + 피아노(piano) | 이 프로젝트의 주 용도(노래 반주 악보) |
| 02_피아노만 | 피아노(piano) | 없는 트랙(목소리·드럼·베이스)을 '없음'으로 판단하는지 |
| 03_밴드 | 목소리 + 피아노 + 베이스 + 드럼 | 4개 트랙을 모두 나누는지 |

- 문제지: `problem.wav` = 정답 트랙들을 그대로 더한 음원
- 피아노 정답은 피아노 트랙이 있는 모델(htdemucs_6s)에서는 piano, 없는 모델(htdemucs)에서는 other와 비교한다
- 정답지: `answer_<트랙>.wav`(악기별 음원), `answer.json`(있어야/없어야 하는 트랙)
- 점수
  - 닮음(dB): 분리한 트랙이 정답 트랙과 얼마나 같은지. 클수록 좋음(10 이상이면 쓸 만함)
  - 새어나옴(dB): 없어야 하는 트랙에 남은 소리 크기. 작을수록 좋음(-20 이하면 거의 없음)
  - 있다고_판단: 들림 정도로 '이 악기가 있다'고 본 결과가 정답과 맞는지

```bash
uv run python tests/benchmark/separation_set.py build   # 문제지·정답지(음원) 만들기
uv run python tests/benchmark/separation_set.py grade   # Demucs로 분리해 채점(몇 분)
```

주의: 문제의 '목소리'는 진짜 사람 소리가 아니라 사운드폰트의 '우~' 소리다.
Demucs는 진짜 목소리로 배운 AI라 이 소리를 목소리로 잘 못 나눌 수 있다(실제 노래 녹음보다 어려운 문제).

| 노래와_피아노 · 피아노 | -0.5 | **7.3** |
| 피아노만 · 피아노 | 44.0 | 31.9 |
| 밴드 · 목소리 / 피아노 | 2.6 / -2.2 | **8.1 / 4.0** |

'있다/없다' 판단: htdemucs 12/12, htdemucs_6s 18/18 (모두 맞음).
처음에는 6s에서 2개가 틀렸다(밴드의 작은 피아노를 '없음', 노래와_피아노의 other를 '있음').
이름 있는 트랙은 -30dB, 6트랙 모델의 other(새어 나온 소리 모음)는 -8dB를 기준으로 바꿔 고쳤다.

## C단계: 음 인식 (`note_set.py`)

- 문제지: B단계 피아노 3곡(4박자·왈츠·6/8) + A단계 여러 악기 2곡(노래+피아노, 밴드). 음원은 A·B단계 build로 만든 것을 다시 쓴다.
- 정답지: `notes/<문제>/answer.json` — 트랙마다 [음높이, 시작(초), 끝(초)]. 곡을 만든 MIDI에서 뽑음.
- 점수: 시작_F1(음높이 같고 시작 ±0.05초), 길이까지_F1(끝 시각도 맞아야 함). 1이 만점.

```bash
uv run python tests/benchmark/note_set.py build
uv run python tests/benchmark/note_set.py grade   # 결과: output/benchmark/notes_채점.json
```

## D단계: 리듬 (`rhythm_set.py`)

C단계에서 찾은 음(초 단위)을 B단계의 박에 맞춰 악보에 쓸 위치·길이로 바꾸는지 시험한다.
위치·길이는 4분음표 단위 분수(1 = 4분음표, 1/2 = 8분음표, 1/3 = 셋잇단 8분음표, 3/2 = 점4분음표).

| 문제 | 시험하는 것 |
|---|---|
| 01~05 | B단계 피아노 곡 그대로(4/4, 왈츠, 6/8, 빠르기 변화, 못갖춘마디) |
| 06_리듬_여러가지 | 점음표, 16분음표, 셋잇단, 당김음, 쉼표, 온음표 |

- 정답지: `answer.json`의 notes = [음높이, 위치, 길이]. 곡 정의에서 바로 뽑는다
- 점수: 위치_F1(위치 맞힘), 길이_정확도(위치 맞힌 음 중 길이도 맞힘), 둘다_F1
- 정답_입력(박·음을 정답에서 가져와 리듬 단계만 시험)과 실제_입력(음원 분석 결과로 시험) 두 가지로 채점

```bash
uv run python tests/benchmark/rhythm_set.py build
uv run python tests/benchmark/rhythm_set.py grade
```

## E단계: 화음 (`chord_set.py`)

D단계에서 박에 맞춘 음을 보고 구간마다 코드(CM, Am7, CM/E …)를 정하는지 시험한다.

| 문제 | 시험하는 것 |
|---|---|
| 01~06 | B단계 곡 그대로(4/4, 왈츠, 6/8, 빠르기 변화, 못갖춘마디, 드럼 밴드) |
| 07_화음_여러가지 | 단3화음, 7화음(Dm7·G7·CM7·FM7·A7·E7), 감·증3화음, 반감7화음, 자리바꿈(CM/E·Dm/F·GM/B), 한 마디에 코드 두 개, 꾸밈음 |

- 정답지: `answer.json`의 chords = [시작, 끝, 이름] (4분음표 단위, 코드 없는 곳은 "N")
- 점수: 16분음표 칸마다 비교해 맞은 시간 비율. 근음_정확도 / 코드_정확도(종류까지) / 자리바꿈까지_정확도

```bash
uv run python tests/benchmark/chord_set.py build
```

  하나뿐이면 선율일 수 있어 센다(07번에서 반 박 일찍 잡힌 라(A) 때문에 Bm7b5를 Bdim으로 읽던 것 방지).
  드럼 밴드에서 G 마디 첫 박에 앞 코드(Dm)가 섞여 Bm7b5/A로 읽던 것이 고쳐졌다(낮은 G 베이스를 못 찾은 마디도).
- 약점: 실제 음원에서 피아노 음이 짧게 잡히면 맨 아래 음이 바뀌어 자리바꿈을 잘못 붙인다.

### G단계 결과 (2026-11-22, `analysis/structure.py`)

- 5곡 모두 정답_입력·실제_입력에서 경계 1.0 / 이름_짝 1.0.
- 처음에는 실제_입력 곡 끝의 남은 울림이 짧은 마디를 만들어 꼬리 부분이 하나 더 생겼고(경계 0.857),
  못갖춘마디 곡은 첫 구절을 다른 구절로 봤다(이름_짝 0.734). 짧은 꼬리는 앞 마디에 붙이고 못갖춘마디는 비교에서 빼서 고쳤다.
- 약점: 구절을 4마디로 고정해 나눈다. 2·3마디 전주나 6마디 구절처럼 4마디 틀에서 벗어나는 곡, 조금씩 바뀌는 반복(A')은 아직 시험하지 않았다.

## H단계: 표현 (`expression_set.py`)

음원 소리를 재서 셈여림(p, f, <, >)과 오른쪽 페달 밟는 곳을 찾는지 시험한다. 곡은 모두 새로 만들었다.

| 문제 | 시험하는 것 |
|---|---|
| 01_셈여림 | 4마디씩 p → f → mp → ff |
| 02_점점 | p → 점점 세게(<) → f → 점점 여리게(>) → p |
| 03_페달_분산화음 | 앞 8마디는 마디마다 페달, 뒤 8마디는 페달 없음 |
| 04_페달_선율 | 선율 + 화음. 앞 8마디만 페달 |

- 정답지: `answer.json`의 marks(마디마다 셈여림 글자 또는 < >), pedals([시작, 끝], 4분음표 단위)
- 점수: 셈여림_정확도(마디마다 맞은 비율) / 한단계_안(p와 mp처럼 한 단계 차이까지 맞음) / 페달_정확도(밟음·뗌이 맞은 시간 비율) / 페달_F(밟는 곳을 반 박 안에서 맞힘)

```bash
uv run python tests/benchmark/expression_set.py build
uv run python tests/benchmark/expression_set.py grade
```

|---|---|---|---|

- 음 인식기(D단계)가 주는 세기는 크기가 고르게 맞춰져 나와(p든 ff든 90 안팎) 쓸 수 없었다. 그래서 음원에서 음을 친 순간 소리 크기를 직접 잰다.
- 페달은 '음 뒤로 음이 두 번 더 나오기 직전에 그 음 높이 소리가 얼마나 남았는지'로 찾는다. 페달을 밟으면 약 -16dB, 안 밟으면 약 -33dB.
- 02_점점: 점점 세게가 한 마디 일찍 시작한다. Am·F 마디가 다른 마디보다 조금 작게 재져서 그렇다.
- 처음에는 E단계가 한 마디 코드를 반 마디씩 나눠(CM → CM/G 등) 페달도 반 마디마다 다시 밟은 것으로 나왔다(실제_입력 페달_F 0.8·0.727). 뿌리음이 같거나 반 마디보다 짧은 코드 구간은 페달 한 번으로 묶어 고쳤다.
- 약점: 셈여림 눈금은 이 문제지 음원 크기에 맞췄다. 녹음 크기가 다르면 전체가 한쪽으로 밀릴 수 있다(바뀌는 곳·< >는 그대로 맞음). 피아노 한 대 소리만 시험했다.

## I단계: 멜로디·가사 (`melody_set.py`)

음 중에서 멜로디(한 줄 선율)를 고르고, 가사 글을 멜로디 음에 붙이는지 시험한다. 곡과 가사는 모두 새로 만들었다.

| 문제 | 시험하는 것 |
|---|---|
| 01_선율_화음 | 8분음표 선율 + 박마다 화음 + 베이스 |
| 02_긴음_분산화음 | 2분음표 선율이 울리는 동안 아래에서 8분음표 분산화음이 움직임 |
| 03_가사_구절 | 2마디 구절 8개(끝에 4분쉼표) + 가사 8줄(이어 부르기 '-' 포함) |

- 정답지: `answer.json`의 melody([음, 시작, 길이], 4분음표 단위), lyrics([시작, 글자])
- 점수: 선율_F(높이 같고 시작이 1/4박 안인 멜로디 음을 맞힌 정도) / 가사_정확도(정답 글자가 같은 자리 음에 붙은 비율)

```bash
uv run python tests/benchmark/melody_set.py build
uv run python tests/benchmark/melody_set.py grade
```
